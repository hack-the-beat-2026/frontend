## 1. 게임 개요

### 1.1 한 줄 요약

파티 참가자를 **숨는 사람**과 **찾는 사람**으로 나누고, 숨는 사람이 앱으로 파티 장소를 촬영해 그 배경에 맞춰 **2D 사람 모형(실루엣)을 색칠(위장)**한 뒤, 주최자가 이를 **종이로 출력·배부**하면 숨는 사람이 실제 공간에 종이를 숨기고 찾는 사람이 이를 찾아 **QR을 스캔**하는 오프라인+온라인 하이브리드 숨바꼭질 게임.

### 1.2 원작 참고 (메챠 카멜레온 / めっちゃカメレオン)

원작은 "칠하고 숨는 그림 숨바꼭질(塗って隠れるお絵かきかくれんぼ)"로, 스테이지를 미리 둘러보고(下見) 캐릭터를 **스포이드(スポイト)로 주변 색을 추출**해 배경에 위장시키는 것이 핵심이다. 원작에는 장면에서 직접 색을 뽑는 **3D 스포이드**와 팔레트에서 뽑는 **팔레트 스포이드**, 그리고 상대를 교란하는 **분신(分身)** 개념이 있다. 본 게임은 이 "색 추출 위장" 재미를 **디지털 화면이 아니라 실제 물리 공간과 종이**로 옮긴 것이 가장 큰 차별점이다.

> 핵심 차별점: (1) 위장 대상이 게임 화면이 아니라 **실제 파티 장소**, (2) 결과물이 **물리적 종이 카드**, (3) 찾기의 판정이 **QR 스캔**으로 이루어짐.

### 1.3 판매/과금 모델 (전제)

- **주최자(Host)가 앱/게임을 구매**하는 사람이다. 즉 유료 사용자는 주최자 1인이며, 참가자는 방 코드/QR로 무료 입장한다.
- 과금 단위(1회 파티권 / 구독 / 인원 상한 등)는 [결정 필요] — 9장 참고.

## 2. 핵심 게임 루프 (한눈에)

```
[주최자] 방 개설 + 설정          →  방 코드/QR 발급
       │
[참가자] 방 코드·QR로 입장        →  로비에서 대기
       │
[주최자] 게임 시작                →  숨는 사람 / 찾는 사람 자동·수동 배정
       │
──────────────── 디자인 단계 (제한시간 A) ────────────────
[숨는 사람] 장소 촬영 → 모형 선택·배치 → 스포이드로 위장 색칠 → 완성 제출
       │
[주최자] 제출된 디자인 수집 → 인쇄용 레이아웃 생성 → 출력 → 카드 배부
       │
──────────────── 은신 단계 (제한시간 B) ────────────────
[숨는 사람] 촬영했던 실제 위치에 종이 카드를 숨김
       │
──────────────── 탐색 단계 (제한시간 C) ────────────────
[찾는 사람] 파티장을 돌아다니며 위장된 카드 발견 → QR 스캔
       │
[시스템] 스캔된 카드 = 발각(탈락) 처리, 은신 사진 공개(리빌)
       │
[주최자/시스템] 제한시간 종료 시 승패·순위 판정 → 결과 화면
```

## 3. 사용자 역할 (Roles)

| 역할 | 정의 | 주요 행동 |
|---|---|---|
| **주최자 (Host)** | 앱 구매자, 방을 만들고 진행을 통제 | 방 개설·설정, 게임 시작/단계 전환, 디자인 수집·인쇄, 승패 판정, 진행 모니터링 |
| **숨는 사람 (Hider / 은신자)** | 위장 카드를 디자인하고 실물을 숨김 | 장소 촬영, 모형 디자인, 카드 수령, 물리적 은신 |
| **찾는 사람 (Seeker / 추격자)** | 숨겨진 카드를 찾아 스캔 | 파티장 탐색, 카드 발견, QR 스캔, 리빌 확인 |

> 주최자는 진행자 역할에 집중할 수도, 동시에 숨는/찾는 사람으로 참여할 수도 있다(겸직 허용 여부는 [결정 필요]).

## 4. 기능 명세 (역할별)

### 4.0 공통 기능

- **방 입장**: 방 코드(예: 6자리 영문+숫자) 입력 또는 QR 스캔으로 입장.
- **닉네임 설정**: 입장 시 표시 이름 지정(중복 방지 또는 자동 접미사).
- **접속 상태 표시**: 로비/게임 중 각 참가자의 온라인 여부, 진행 상태(디자인 중/제출 완료/은신 완료 등).
- **실시간 동기화**: 단계 전환, 남은 시간, 참가자 상태가 모든 기기에 즉시 반영.
- **남은 시간 타이머**: 현재 단계의 제한시간을 크게 표시(주최자가 설정한 값).
- **알림/안내**: 단계 전환, 마감 임박(예: 30초 전), 발각 등 이벤트 배너·진동·사운드.
- **재접속 복구**: 네트워크 끊김 후 재입장 시 이전 상태(역할·제출물·진행)를 복원.

### 4.1 주최자 (Host) 기능

**방 관리**

- 방 개설: 방 이름, 최대 인원 설정 후 생성.
- 방 코드 + 입장용 QR 자동 발급(화면 표시·복사·공유).
- 참가자 목록 조회 및 강퇴, 방 잠금(추가 입장 차단).

**게임 설정**

- 역할 분배 방식: 자동(비율/인원 지정) 또는 수동 지정. 예) 숨는 사람 N명, 찾는 사람 M명.
- 제한시간 3종을 개별 설정(웹 화면에 표시됨):
  - 디자인 단계 시간(A)
  - 은신 단계 시간(B)
  - 탐색 단계 시간(C)
- 숨는 사람 1인당 제작 가능한 모형 수: **1개로 고정**(미끼/분신 카드는 사용하지 않음 — 확정).
- 승리 조건 프리셋 선택(8장 참고).

**진행 통제**

- "게임 시작" / 각 단계 "다음 단계로" 강제 전환, 일시정지, 조기 종료.
- 실시간 대시보드: 제출된 디자인 수, 은신 완료 수, 발각된 카드 수, 남은 시간.

**디자인 수집 & 인쇄** (본 게임의 핵심 산출물)

- 제출된 모든 디자인을 갤러리로 확인.
- **인쇄용 레이아웃 자동 생성**: 각 카드에 대해 앞면(디자인) + 뒷면(QR) + 절취선을 포함한 인쇄 파일(PDF) 생성.
- 용지 규격(A4 등), 한 장당 카드 수, 양면/단면 모드 선택.
- 인쇄 미리보기 및 다운로드/바로 인쇄.
- (선택) 카드별 라벨(숨는 사람 닉네임/번호) 표시 여부.

**결과/판정**

- 탐색 단계 실시간 발각 현황.
- 종료 시 승패·순위 자동 판정 및 결과 화면 표시·공유.

### 4.2 숨는 사람 (Hider) 기능

**장소 촬영**

- 앱 내 카메라로 숨기고 싶은 실제 장소 촬영(재촬영 가능).
- 촬영한 사진을 디자인 캔버스의 배경으로 사용.

**모형 선택 & 배치**

- 흰색 2D 사람 모형(실루엣) 라이브러리에서 하나 선택(다양한 포즈/체형 제공).
- 사진 위에 모형을 드래그로 배치, 크기 조절, 회전, 좌우 반전.

**위장 색칠 (스포이드 기반)**

- **사진 스포이드**: 배경 사진의 임의 지점을 탭하면 그 픽셀 색을 현재 색으로 추출(원작의 3D 스포이드에 대응).
- **팔레트**: 추출한 색 저장·재사용, 기본 색상 팔레트 제공.
- 브러시로 모형 영역 색칠(브러시 크기 조절), 영역 채우기(fill), 지우개.
- 실행취소/다시실행.
- (선택) 모형을 부위별 영역으로 분할해 부위 단위 색칠.
- 실시간 미리보기: 색칠된 모형이 배경에 얼마나 잘 위장되는지 확인.

**완성 & 제출**

- "완성" 버튼 → 디자인(모형 이미지) + 은신 사진이 주최자에게 전송.
- 제출 후 대기 화면(카드 수령 안내), 마감 전 수정 허용 여부는 [결정 필요].

**카드 수령 & 은신**

- 주최자로부터 종이 카드를 받은 뒤, 앱에서 "은신 완료" 체크(선택 — 진행 현황 반영용).
- (선택) 실제 숨긴 위치를 앱에 기록.

### 4.3 찾는 사람 (Seeker) 기능

**탐색 & 스캔**

- 앱 내 QR 스캐너로 발견한 카드의 QR 스캔.
- 스캔 성공 시(= QR이 카드 뒷면에 있어 카드를 떼어 뒤집어야만 스캔 가능 → **물리적 발각 확정**):
  - 해당 카드 = 발각(탈락) 처리.
  - **리빌 화면**: 숨는 사람이 촬영했던 은신 사진 + (선택) 위장 디자인/닉네임 공개("이렇게 숨겼어요").
  - 본인 점수/찾은 카드 수 갱신.
- 이미 발각된 카드·타 세션 QR 스캔 시 안내(중복/무효 처리).

**현황**

- 남은 미발각 카드 수(총 N개 중 M개 발견), 남은 시간, 개인 랭킹.

## 5. 화면 흐름 (Screen Flow)

**주최자**

```
스플래시/로그인 → 방 개설·설정 → 로비(코드·QR·참가자) → 게임 설정 확인
 → [디자인 단계] 제출 현황 → 인쇄 화면(미리보기·출력) → [은신 단계] 현황
 → [탐색 단계] 발각 현황 → 결과 화면
```

**숨는 사람**

```
입장(코드/QR) → 닉네임 → 로비 대기 → 역할 안내(숨는 사람)
 → [디자인] 카메라 촬영 → 모형 선택·배치 → 스포이드 색칠 → 완성 제출 → 대기
 → 카드 수령 안내 → [은신] 은신 완료 체크 → [탐색] 생존/발각 상태 → 결과
```

**찾는 사람**

```
입장(코드/QR) → 닉네임 → 로비 대기 → 역할 안내(찾는 사람)
 → 대기(디자인·은신 단계) → [탐색] QR 스캐너 → 스캔 성공 시 리빌 → 현황 → 결과
```

## 6. 유저 시나리오 (역할별, 단계별)

### 6.1 주최자 시나리오 — "민준(파티 주최자)"

1. 민준은 앱을 구매하고 로그인한 뒤 "방 만들기"로 파티 방을 개설한다.
2. 숨는 사람 4명 / 찾는 사람 3명, 디자인 10분 · 은신 5분 · 탐색 15분으로 설정한다.
3. 화면에 뜬 QR과 방 코드를 파티장 TV/자기 폰으로 공유하고, 친구들이 입장하는 것을 로비에서 확인한다.
4. 전원 입장 후 "게임 시작"을 누르자 역할이 배정된다.
5. 디자인 단계 동안 제출 현황(4명 중 3명 완료)을 지켜보다, 전원 완료되어 다음 단계로 넘긴다.
6. "인쇄" 화면에서 앞면 디자인·뒷면 QR·절취선이 포함된 A4 PDF를 미리보고 출력한다.
7. 출력물을 절취선대로 잘라 각 숨는 사람에게 나눠 준다.
8. 은신 단계 → 탐색 단계로 진행하며 발각 현황을 지켜본다.
9. 탐색 시간이 종료되자 결과 화면이 뜨고, 끝까지 안 잡힌 지수(숨는 사람)가 최종 생존자로 발표된다.

**예외/엣지**

- 홀수 인원·인원 부족: 최소 인원 미달 시 시작 차단 안내.
- 지각 입장: 방 잠금 전까지 허용, 게임 시작 후 입장 처리 정책 [결정 필요].
- 프린터 문제: PDF 재다운로드/재인쇄, 특정 카드만 재출력.
- 참가자 이탈: 디자인 미제출자 처리(자동 제외/기본 모형 대체) [결정 필요].

### 6.2 숨는 사람 시나리오 — "지수"

1. 지수는 QR을 찍어 방에 입장하고 닉네임을 정한다.
2. 게임이 시작되고 "숨는 사람" 역할을 받는다. 10분 타이머가 크게 표시된다.
3. 거실 책장 앞으로 가서 앱 카메라로 책등이 늘어선 배경을 촬영한다.
4. 서 있는 자세의 사람 모형을 골라 책 사이 틈에 배치하고 크기를 줄인다.
5. 사진 스포이드로 책등의 갈색·남색을 번갈아 추출해 모형을 세로 줄무늬로 칠해 위장한다.
6. 미리보기로 배경에 잘 묻히는 것을 확인하고 "완성"을 눌러 제출한다.
7. 주최자에게서 인쇄된 카드를 받아, 촬영했던 그 책장 틈에 실제로 끼워 숨기고 앱에서 "은신 완료"를 누른다.
8. 탐색 단계 동안 자신의 카드가 아직 발각되지 않았음을 상태 화면으로 확인하며 생존한다.

**예외/엣지**

- 저조도/흔들림: 촬영 재시도 안내, 밝기 보정 [선택].
- 시간 초과: 미완성 시 현재까지 디자인 자동 제출 또는 미제출 처리 [결정 필요].
- 카드 훼손/분실: 재출력 요청 흐름.

### 6.3 찾는 사람 시나리오 — "현우"

1. 현우는 방 코드로 입장해 "찾는 사람" 역할을 받고, 디자인·은신 단계 동안 대기 화면을 본다.
2. 탐색 단계가 시작되자 15분 타이머와 함께 "총 4개 중 0개 발견"이 표시된다.
3. 파티장을 돌며 벽·화분·책장 등을 살핀다. 책장 틈에서 주변과 비슷한 색의 종이 사람을 발견한다.
4. 앱 스캐너로 카드 뒷면 QR을 찍자 "발각!" 리빌 화면에 지수의 은신 사진과 위장 디자인이 뜬다.
5. 점수가 오르고 "4개 중 1개 발견"으로 갱신된다. 계속 탐색을 이어간다.
6. 시간이 끝나 3개만 찾았고, 마지막 1개는 못 찾아 해당 숨는 사람이 승리한다.

**예외/엣지**

- QR 인식 실패: 조명/거리 안내, 수동 코드 입력 대체 [선택].
- 부정 스캔: 게임 세션에 바인딩되지 않은 QR·타인이 이미 스캔한 카드 처리.
- 동시 스캔: 한 카드를 두 명이 거의 동시에 스캔할 때 최초 1인만 인정.

## 7. 인쇄물(카드) 사양

- **앞면**: 숨는 사람이 완성한 위장 모형 이미지(가급적 실루엣 외곽선을 따라 오릴 수 있도록 여백/외곽선 제공).
- **뒷면**: 해당 카드에 고유하게 매핑된 QR 코드(스캔 시 리빌 페이지로 연결). **QR은 벽·물체에 붙였을 때 보이지 않는 뒷면에 위치**하는 것이 핵심 설계로, 찾는 사람이 QR을 스캔했다는 것은 곧 **종이를 실제로 떼어내 뒤집었다**는 뜻이다. 즉 "멀리서 보기만 한" 것이 아니라 물리적으로 손을 대 발견한 경우에만 발각이 성립하는 **판정 장치** 역할을 겸한다. (따라서 QR은 부착 시 반드시 가려지는 면에 인쇄되도록 레이아웃을 잡아야 함.)
- **절취선**: 카드 단위(또는 모형 외곽) 절취 가이드.
- **인쇄 방식 옵션**:
  - 양면 인쇄(앞=디자인, 뒤=QR): 가장 자연스러우나 가정용 프린터의 앞뒤 정렬 오차 주의.
  - 단면 인쇄 후 접기/붙이기(디자인과 QR을 나란히 배치 → 반으로 접어 뒷면 QR 완성): 정렬 부담 없음. → **기본값으로 확정**.
- **QR 페이로드**: 방/세션 ID + 카드 ID(+서명)로 구성해 위·변조·타 세션 스캔을 방지.
- **크기**: 실제 은신에 적합한 카드/모형 실물 크기 규격화 필요 [결정 필요].

## 8. 게임 규칙 & 승패 판정

**기본 판정 (사용자 설명 기준)**

- 탐색 제한시간 내 **찾는 사람이 모든 카드를 스캔(발각)** 하면 → **찾는 사람 승**.
- 시간 종료 시 **하나라도 발각되지 않은 카드가 남으면** → **숨는 사람(팀) 승**.
- **최종 생존자(MVP)**: 가장 늦게까지 발각되지 않은 숨는 사람.

**선택 가능한 승리 조건 프리셋(주최자 설정)**

- 팀전: 위 기본 규칙(숨는 팀 vs 찾는 팀).
- 개인 생존전: 숨는 사람은 생존 시간이 길수록 상위 랭킹, 찾는 사람은 스캔 수로 랭킹.
- 혼합: 팀 승패 + 개인 MVP 동시 시상.

**부정행위 방지 / 발각 판정**

- **물리적 발각 보장**: QR이 카드 뒷면(부착 시 가려지는 면)에 있어, 카드를 실제로 발견·분리해 뒤집어야만 스캔이 가능 → 스캔 = 진짜 발각으로 확정, "멀리서 봤다"식 애매한 발각은 원천 배제.
- QR은 세션·카드에 바인딩되어 다른 방/미리 캡처한 QR로는 무효.
- 카드별 최초 스캔만 인정(중복 무효).

## 9. 열린 질문 / 결정 필요 사항

- 과금 단위: 1회 파티권 / 구독 / 인원 상한제 중 무엇인가.
- 주최자의 게임 참여(숨는·찾는 겸직) 허용 여부.
- 디자인 제출 후 마감 전 수정 허용 여부.
- 미제출·미완성·중도 이탈 참가자 처리 정책.
- 카드/모형 실물 크기 규격.
- 리빌 화면 공개 범위(사진만 / 사진+디자인 / +닉네임).
- 은신 사진의 저장 기간·개인정보 처리 방침(파티장 사진 포함).

**확정된 결정 (Decision Log)**

- 제한시간은 **디자인 / 은신 / 탐색 3단계로 분리**하고 각각을 주최자가 개별 설정한다.
- 인쇄는 **단면 인쇄 후 반으로 접어 뒷면 QR을 완성**하는 방식을 기본값으로 한다.
- **미끼(분신) 카드는 사용하지 않는다.** 숨는 사람 1인당 카드 1장으로 고정.
- QR 스캔 = **물리적 발각 확정**(QR은 부착 시 가려지는 뒷면에 배치).

## 10. 기술 스택 / 아키텍처 제안

> "웹뷰로 일단"이라는 전제에 맞춰, **웹 기반 SPA + 얇은 네이티브 셸** 구조를 권장한다. 카메라·QR·인쇄가 핵심이라 브라우저 권한 처리와 실시간 동기화가 관건이다.

### 10.1 클라이언트

- **프레임워크**: React(또는 Vue) 기반 SPA. 반응형·모바일 우선 UI.
- **셸/배포 형태**:
  - 빠른 검증: **PWA**(설치형 웹앱) — `getUserMedia`로 카메라, 웹 QR 스캔.
  - 안정적 카메라/권한: **Capacitor**(또는 React Native WebView)로 감싼 웹뷰 — iOS Safari 웹뷰의 카메라 제약을 네이티브 브릿지로 우회. → 1차 웹뷰 방향과 정합.
- **카메라 촬영**: `getUserMedia` / 네이티브 카메라 플러그인.
- **스포이드·색칠**: HTML5 **Canvas** — 사진을 캔버스에 그린 뒤 `getImageData`로 픽셀 색 추출, 브러시/채우기/실행취소는 캔버스 드로잉 + 상태 스택으로 구현.
- **QR 스캔**: `html5-qrcode` / ZXing 또는 네이티브 스캐너 플러그인.

### 10.2 실시간 통신 & 백엔드

- **실시간 상태 동기화**(로비, 단계 전환, 타이머, 발각 이벤트): 아래 중 택1
  - **Firebase(Firestore/Realtime DB) 또는 Supabase Realtime**: 방/참가자/상태 모델을 빠르게 구축, 서버 코드 최소화. → MVP 권장.
  - **자체 서버 + WebSocket(Socket.IO)**: NestJS/Express, 세밀한 게임 로직·권위(server-authoritative) 제어가 필요할 때.
- **게임 상태 머신**: `LOBBY → ROLE_ASSIGN → DESIGN → PRINT → HIDING → SEEKING → RESULT`를 서버 권위로 관리(클라이언트는 표시·입력만).
- **인증**: 주최자만 계정 로그인(구매 연동), 참가자는 방 코드 기반 익명 세션 토큰.

### 10.3 저장소 & 미디어

- **이미지 저장**(은신 사진, 완성 디자인): 오브젝트 스토리지(S3 / Cloudflare R2 / Firebase Storage).
- **데이터 모델(개략)**: `Room`, `Player(role, status)`, `Card(hiderId, designImg, hidingPhoto, qrToken, foundBy, foundAt)`, `GameState`.

### 10.4 인쇄 & QR

- **QR 생성**: `qrcode` 라이브러리, 페이로드는 `roomId + cardId + 서명(HMAC)`.
- **인쇄 레이아웃(PDF)**:
  - 서버 렌더링: Puppeteer로 HTML 레이아웃 → PDF(정교한 절취선·양면 정렬에 유리).
  - 클라이언트 렌더링: `jsPDF` / `pdf-lib`로 즉시 생성.
- **리빌 페이지**: QR의 URL은 방·카드에 바인딩된 결과 페이지로 연결, 스캔 시 발각 처리 + 은신 사진 표시.

### 10.5 구성 요소 요약

```
[참가자 웹뷰]──실시간──[상태 백엔드(Firebase/Supabase or WS 서버)]──[오브젝트 스토리지]
      │                          │
   카메라/스포이드/QR         게임 상태 머신
      │                          │
[주최자 웹뷰]──인쇄요청──[PDF/QR 생성]──▶ 프린터
                                   ▲
                            (QR 스캔 → 리빌/발각 처리)
```
